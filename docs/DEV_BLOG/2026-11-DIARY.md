# Development Diary — November 2026

## 13 November 2026

- Started the Generals Mod Fusion work on the dedicated `claude/generals-mod-fusion` branch.
- Audited the Android launcher and confirmed that managed multi-mod loading already exists through `ModManager`, `ModAnalysis`, `ModPacker`, and the engine's active-mod list.
- Confirmed that the existing feature is priority-based archive mounting, not semantic merging of INI definitions or faction/UI registries.
- Added the Fusion implementation plan. The first milestone is a validated archive reader and a conservative preflight report; no source archives will be modified.
- No Android build or GitHub Actions workflow was run in this session.

- Implemented the first read-only Fusion layer: BIGF archive validation and selected-mod archive preflight with duplicate virtual-path reporting. These classes are not yet wired into the launcher and do not generate a playable merged archive.

- Added bounded BIGF entry reads and a conservative INI declaration index. Fusion preflight now scans INI entries inside BIGF archives and reports repeated named definitions with source locations; it remains diagnostic-only and does not rewrite INI files or build a playable Fusion archive.

- Added a heuristic typed-reference scanner for common INI assignments and extended preflight to compare those references against declarations indexed in the selected mod archives. References not found in the selected set are reported as informational warnings because retail game data, loose INI files, and inherited definitions are not yet indexed. This is not yet a full transitive dependency resolver.

- Added a candidate dependency-graph layer over the current INI declaration/reference index, including declared parent/inheritance links, and exposed it through the preflight result. The graph is intentionally advisory: current references are associated at INI-file granularity rather than exact block scope, so it can over-approximate dependencies. No automatic merge or playable Fusion package is claimed.

- Corrected the reference scanner's block model to follow Generals-style `End` terminators and nested module blocks rather than C-like braces. Dependency tracing now indexes references by owner once before graph traversal, avoiding repeated full scans of the reference index. The scanner remains conservative and heuristic: unsupported block forms, dynamic names, and macro-driven references can still be missed. No playable semantic merge, launcher UI, APK build, or device validation has been completed.

- Added `FusionBigArchiveWriter.java`, a bounded streaming BIGF writer for validated source entries. It rejects duplicate normalized virtual paths, enforces the BIGF 2 GB signed-size limit, writes to a temporary file, reopens the result with `FusionBigArchive`, and checks the output table before publishing. This is an archive assembly primitive only: it does not merge duplicate INI definitions, reconcile faction/UI registries, or prove that a combined mod is playable. It is not yet called by the launcher, and no Android build/device test has been run.

- Added `FusionArchiveBuild.java` to orchestrate a strict first archive-build path: it reruns preflight, refuses malformed inputs, duplicate virtual paths, and duplicate named INI definitions, verifies that the output is outside every selected source mod folder, inventories source BIGF entries, and delegates to the streaming writer. This intentionally supports only non-overlapping archive contents. It does not merge same-path INI files, resolve faction/UI conflicts, copy loose files, or establish gameplay compatibility. The class is not yet wired to the launcher; no local Android build or device test was available/performed.

- Hardened BIGF publication: the writer now uses a unique temporary file, preserves an existing destination until the replacement is ready, attempts an atomic move, and restores the prior output if publication fails. It rechecks source archive lengths during copying and verifies each output entry offset.
- Added a strict preflight blocker for loose game-layout files. The current archive builder reads BIGF only; it now refuses mods containing loose files in recognized game roots rather than producing an incomplete archive that appears successful. Loose-file integration remains future work.

- Follow-up writer audit found and corrected path inconsistencies around canonical output publication. The writer now rejects directory/symlink destinations, handles short destination names for temporary files, and uses the canonical destination consistently for atomic move, fallback rename, and rollback. This code has not yet been compiled or exercised on Android.

- Additional Fusion safety audit: reject lossy ISO-8859-1 BIGF path conversions, use unique per-build backup names, reject symlink output paths before canonicalization, validate empty selections before scanning, and block unsupported .gib archives rather than silently omitting them. No build or device test was run.

- Fusion archive build now deduplicates repeated virtual paths only when SHA-256 of streamed entry bytes matches; conflicting contents still stop the build. Unique entries are not hashed. This is not INI semantic merging; duplicate named definitions remain blocked. No compile/device test.

- Refined Fusion preflight INI indexing: byte-identical copies of the same normalized INI virtual path are indexed once, while distinct content variants for that path are each indexed once. This prevents repeated archive copies from inflating duplicate-definition/reference diagnostics without hiding genuinely different INI content. Source-level change only; no Android build/device test.

- Improved the typed-reference scanner's End-block tracking for a defined set of common bare nested headers (including DefaultConditionState, ModelConditionState, WeaponSet, and Turret). This reduces premature owner closure while retaining conservative handling of unknown syntax. The scanner remains heuristic; no automated build or device validation.

- Hardened archive input selection: duplicate canonical mod roots and unsafe/missing source roots are rejected, and archive traversal is sorted for reproducible output ordering. Removed a no-op branch from the builder. Source-only; no Gradle build or device test was run.


- Added a conservative INI scope diagnostic pass and connected it to Fusion preflight. It reports unmatched recognized `End` tokens and unclosed recognized declaration/nested scopes with source and line numbers. The pass is warning-only because the current lexical model does not cover all Generals INI syntax; it does not merge or rewrite INI content. No Android compile or device test was run.

- Refined Fusion INI structural diagnostics to track recognized declaration and nested-block scopes with explicit frames and opening line numbers. Premature declarations and EOF scope failures now identify the affected declaration/block more precisely. The pass remains warning-only and has not been compiled or tested against a representative mod corpus.

- Improved Fusion conflict reporting: duplicate INI declaration errors now list the exact definition keys and source archive/file line numbers (up to 20 entries), with parent names where available. Duplicate virtual path summaries are also available from preflight. Conflicts remain blocking; no automatic winner is chosen. Not yet compiled or tested on device.

- Added source-aware virtual-path conflict errors. When selected archives contain different data for the same virtual path, the builder now identifies the source mod/archive names instead of only naming the path. The collision is still rejected; no arbitrary load-order winner is chosen.

- Clarified the Fusion product requirement as generic N-mod support, not a hardcoded TEOD/Hypersonic pair. The architecture must analyze arbitrary selected Zero Hour mods by content domain, preserve provenance across all inputs, classify automatic/user-assisted/manual-adapter/unsupported cases, and validate three-or-more-mod combinations. This is a requirements update; it does not claim those merge capabilities are implemented.

- Added a conservative named-declaration block extractor for Generals INI. It preserves raw block text and source locations, flags unrecognized bare syntax as unsafe for automated comparison, and is now part of preflight diagnostics. It does not yet merge declarations or produce playable Fusion output; no compilation or device test has been run.

- Added N-way duplicate INI definition classification across all selected mods: exact byte-identical, differing content, or unsafe to compare. Reports retain every source and line range. This is diagnostic only; no definition is silently chosen and duplicate declarations remain blocked. No compile/test/device validation has been run.

- Exposed N-way INI conflict classifications as structured Fusion preflight data, with per-status counts and bounded source summaries. This prepares the future report UI to consume typed conflict records instead of parsing warning text. Duplicate definitions remain blocked; exact byte identity alone is not proof that the containing INI files can be safely combined. Source-only change; no compile or device test.

- Added JUnit coverage for the conservative INI block extractor and N-way conflict classifier: CRLF byte preservation and source line ranges, unknown-syntax safety, three-way exact duplicates, three-way divergent definitions, and unsafe participants. Added the JUnit test dependency. Tests are committed but have not been executed because no local Android/Gradle build environment is available in this workflow.

- Expanded parser/conflict regression coverage: case-insensitive definition grouping across three sources, declaration-type separation, final blocks without trailing newlines, and null/empty analyzer inputs. Tests are committed but remain unexecuted; no Gradle build was run.

- Hardened the new INI analysis result model with defensive copies and unmodifiable lists for parsed blocks, parser warnings, uncertainty details, and conflict participants. This prevents later report/UI code from mutating the preflight evidence. Source-only change; compile and tests remain pending.

- Deep-froze all nested collections in FusionPreflight.Result (source-path, definition, reference, and outside-selection maps), not only their outer maps. Callers can no longer mutate the inventory by editing a list obtained from a result. No build/test execution.

- Encapsulated the exact source bytes of extracted INI blocks: callers now receive defensive byte copies, while the classifier compares blocks through a read-only equality method. Corrected Java test fixture newline escapes and verified the committed test source text. Tests still have not been run.
